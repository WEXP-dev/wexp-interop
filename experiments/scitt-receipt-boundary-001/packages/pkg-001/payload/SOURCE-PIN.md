# Source of the Receipt

| | |
|---|---|
| implementation | SCITT API emulator and interoperability client, `scitt-community/scitt-api-emulator`, a community implementation used in IETF SCITT hackathons; principal contributor by commit count John Andersen (21 commits of the pre-archive history) |
| pinned revision | commit `cfebeee5bb3da7d5a9a13d319aaaab17c1348641`, tag `pre-archive`, 2024-03-26; the repository was archived on 2024-11-22 (`main` = `6e677607`) and is no longer maintained |
| tree algorithm | `CCF` (the emulator's own countersignature receipt: `[sign_protected, [signature, node_cert_der, proof, leaf_info]]`, labels `service_id`, `tree_alg`, `issued_at`); this predates the final COSE Receipts format of RFC 9942 and the label numbers of RFC 9943 (the statement carries CWT claims under label 14 rather than RFC 9943's 15, and a non-standard registration-info header 393; label 394 for receipts matches RFC 9943) |
| how it was run | not pip-installed; the pinned source directory is placed on `PYTHONPATH`, dependencies come from PyPI (`harness/venv-freeze.txt`), and `harness/shim/` satisfies one import of the RKVST SDK that is no longer on PyPI; the RKVST backend is never used |
| what the emulator does at registration | by its own source comment in `scitt_emulator/scitt.py`, `_create_receipt`: "This emulator does not verify the claim signature and does not apply registration policies." It checks that the submission is a COSE_Sign1 with algorithm, content-type and CWT-claims headers, then countersigns and builds a CCF-style inclusion proof over a tree padded with dummy leaves |
| what was verified | `client verify-receipt` recomputed the leaf and root, checked the node signature over the root, and checked that the node certificate was issued by the service certificate in `artifacts/service_parameters.json`: "Receipt verified" |

## Artifacts (bytes as produced on 2026-11-06, digests in `artifacts/SHA256SUMS.txt`)

- `artifacts/signed-statement.cose`: the Signed Statement (COSE_Sign1, algorithm -35 ES384, ad hoc P-384 issuer key generated by the emulator as a did:jwk, subject `wexp-interop:scitt-receipt-boundary-001`, JSON payload naming target `T`).
- `artifacts/receipt.cbor`: the Receipt returned at registration (entry id 1) and identical to the bytes retrieved afterwards with `retrieve-receipt`.
- `artifacts/service_parameters.json`: the emulator's service identity (service certificate, tree algorithm); no private key is included.

`harness/run_emulator.sh <new-dir>` repeats the registration; keys are ad hoc, so bytes differ per run.
The emulator was chosen because it is the referenced hackathon implementation; the TypeScript
reference implementation was not needed as a fallback.
